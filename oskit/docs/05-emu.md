# 05 · 系统模拟器（`oskit emu`）

## 1. 目标与定位

实现一个**用户态指令集模拟器（ISA simulator）**：不借助硬件或虚拟化，用软件
逐条解释执行 **RISC-V RV32I + M 扩展** 程序，并附带最小系统设备模型。
对标"教学版 QEMU-tiny / TinyEMU"：

- 可加载真实 RISC-V 工具链产出的 ELF32 可执行文件直接运行；
- 内置两段手工编码的演示程序（无工具链也能演示全部机制）；
- 支持指令级跟踪（trace），把取指-译码-执行-写回过程完整暴露——
  这正是《计算机组成/操作系统》实验想让学生看见的部分。

非目标：S/U 特权级、MMU、压缩指令(C)、原子指令(A)、浮点、外设齐全的 SoC。
这些在文档末尾列为扩展路线。

## 2. 功能范围

| 能力 | 说明 |
|------|------|
| 指令集 | RV32I 全量（含 fence、ecall/ebreak）+ M（乘除）+ 常用 CSR 读取（cycle/time/instret）|
| 加载器 | ELF32 小端（EM_RISCV），按 PT_LOAD 装入 RAM；`--binary` 平坦模式按 `--base` 装入 |
| 内存 | 线性 RAM（默认 8MiB，`--ram` 调整），物理地址直接访问 |
| 设备 | NS16550 风格 UART（输出/状态）、Exit 设备、mtime 计数器（见内存映射）|
| 系统调用 | Linux 风格 `ecall`：`exit(93)`、`write(64)` —— 兼容简单 Linux 用户程序 |
| 调试 | `--trace`（逐指令反汇编式打印）、`--trace-after N`、`--max N` 指令上限、`--dump-regs`、`--stats` |

## 3. 内存映射（QEMU virt 机的子集）

```
0x8000_0000 ─ 0x8080_0000   RAM（默认 8MiB，--ram 可改）
0x1000_0000 ─ 0x1000_0100   UART（读 0x05=LSR: bit5 THR空；写 0x00=THR 输出到 stdout）
0x0200_BFF8                CLINT mtime（64 位只读，返回已执行指令数）
0x9000_0000                Exit 设备（写入 v → 退出码 v&0xff，仿 sifive test）
```

> 与 QEMU `virt` 机的 UART/CLINT 地址一致：真实 RISC-V 程序里操作这些地址的
> 裸机代码在本模拟器中同样工作。

## 4. 架构

```
┌──────────────────────────────────────────────┐
│ main: 解析参数 → 装载 ELF/flat → 初始化       │
├──────────────────────────────────────────────┤
│ 执行循环 step():                              │
│   fetch  ← mem[pc]（对齐与范围检查）           │
│   decode ← opcode/f3/f7/寄存器/立即数域提取    │
│   execute→ 寄存器堆(0 置恒零)/访存/MMIO/ecall │
│   pc ← next_pc；instret++                     │
├──────────────────────────────────────────────┤
│ MMIO 判定: 地址落在设备区 → 设备读写，否则 RAM │
│ 退出: Exit 设备 / ecall(93) / --max 上限 / 异常│
└──────────────────────────────────────────────┘
```

核心状态：`uint32_t x[32]`（x0 恒 0，写后强制清零）、`uint32_t pc`、
`uint64_t instret`、`uint8_t *ram`。

## 5. 关键实现细节

1. **译码字段**（RV32 规整编码）：
   `opcode=[6:0]`、`rd=[11:7]`、`f3=[14:12]`、`rs1=[19:15]`、`rs2=[24:20]`、
   `f7=[31:25]`；I/S/B/U/J 五种立即数各自拼装并**符号扩展**。
2. **分支/跳转**：JAL/JALR/条件分支计算目标 = pc + 符号扩展偏移；
   JALR 目标 `& ~1u`；执行序列注意"先算 link=pc+4 再改 pc"避免覆盖 rd==rs1 陷阱。
3. **M 扩展语义**：除零时 DIV=-1 / DIVU=0xFFFFFFFF / REM=被除数 / REMU=被除数；
   `INT_MIN / -1` 溢出回 INT_MIN（按 RISC-V 规范，不陷入）。
4. **访存**：小端字节序拼装；模拟器允许非对齐访问（实现简单、语义宽容，已在限制中声明）；
   MMIO 范围先行判定，避免设备地址落入 RAM 缓冲造成误访问。
5. **ecall**：`a7(x17)=93` → exit(a0)；`=64` → write(fd, buf, count) 从模拟内存读出
   写到宿主 stdout/stderr；其余 a7 报错终止。EBREAK → 打印寄存器现场后终止。
6. **ELF 加载**：复用 `elf.c`（ELF32 分支），校验 `EM_RISCV`、PT_LOAD 段落在 RAM
   范围内（0x80000000 起），入口 = e_entry。

## 6. 内置演示程序

- `--demo`：打印 `EMU OK` 后经 Exit 设备退出（码 42）——验证 lui/addi/sb/sw 与 UART/Exit 设备；
- `--demo2`：初始化栈 → 打印 `fib(10)=` → 迭代算斐波那契 → 用 `divu/remu` 逐位转十进制
  经栈缓冲倒序输出 → `fib(10)=55` → 退出码 55——覆盖分支循环、栈操作、M 扩展。

演示程序以手工编码的机器字内嵌于 `src/emu.c`，每条指令带编码注释，
`--trace` 输出可与注释互相印证（这也构成对模拟器译码正确性的自检）。
真实程序无需内置：装了 RISC-V 交叉工具链后 `riscv64-unknown-elf-gcc -march=rv32i_m
-nostdlib ... 生成 ELF` 直接交给 `oskit emu`。

## 7. CLI 接口

```
oskit emu <程序.elf> [选项]        或   oskit emu --demo / --demo2
```

| 选项 | 说明 |
|------|------|
| `--binary` | 按平坦二进制装入（默认按 ELF32 解析）|
| `--base ADDR` | 平坦模式的装载地址（默认 0x80000000）|
| `--ram MiB` | RAM 大小（默认 8）|
| `--trace` | 逐指令打印 `pc: 字节  助记符 操作数` |
| `--trace-after N` | 前 N 条不打印（跳过初始化噪声）|
| `--max N` | 指令上限（默认 5000 万，防死循环）|
| `--dump-regs` | 结束时转储 32 个寄存器 + pc |
| `--stats` | 结束时打印 executed 指令数 |

退出码：被模拟程序的退出码；`124` 表示达到 `--max` 上限；`1` 装载/非法指令错误。

## 8. 验收标准

1. `oskit emu --demo` 输出 `EMU OK` 并以退出码 42 结束；
2. `oskit emu --demo2` 输出 `fib(10)=55` 并以退出码 55 结束；
3. `--trace` 前若干行与源内嵌注释一一对应（抽样核对 lui/addi/sb/sw/bne/divu）；
4. 非法指令（如全 0xFFFFFFFF）触发明确错误报告含 pc 与指令字；
5. `--max 10` 强制截停时统计条数准确。

## 9. 已知限制与扩展路线

- 非对齐访存宽容处理（真机通常陷入，由软件陷阱对齐）；
- 无 CSR 写副作用与中断（mtime 只读、无 timer 中断注入）；
- 扩展路线（由易到难）：A 压缩指令 C → S 模式与陷入 → CLINT 中断 → 简单总线/更多设备 →
  接入 `port gen` 生成内核的启动自测。
